# DEV-002: Evaluation lock without benchmark tooling; no benchmark requests

Recorded: 2026-11-16

## What the protocol says

Protocol v0.3, "Freeze sequence": the evaluation lock commits the final case list together
with the request generator, the baseline implementations and the analysis script. All arms
are then run twice per request, and the analysis script is run unmodified.

## What happened

The final case list (`cohort/`, PR #130, merge commit 80f1c4c) has 10 unique qualifying
pairs: N 2, X 8, E 0, I 0. Under the protocol's "Small or empty cohort" rule:

- Q1 and Q2 (on E) are not estimable: E has zero cases.
- Q1b (E + I) and Q3 (avoid-only arm on E) have empty cohorts and are not estimable.
- Q5 (miss attribution, duplicate rate) and Q6 (strict avoid-only) need benchmark
  responses, and there are no cases to request.
- N and X cases appear only in the coverage report (Q4), by the protocol's rule.
- Q4 (coverage) is computed by `tools/build_cohort.py`, already committed with the case list.

So the request generator, the baseline implementations (B0–B3) and the analysis script are
not built, and no benchmark request is sent to release-4. The evaluation lock tag
`rrb-01-evaluation-lock` is placed on the commit containing this deviation and the final
case list. The SHA-256 of `cohort/cohort.json` is recorded in the tag message.

## Also recorded here

The strict reading of AMD-002 check 1 (omitted words in a quote are not an allowed
difference) was applied when building the cohort. The rows affected are ADJ-057, 058, 059,
060, 063, 065, 066, 068, 070 and 076, which are read as `ambiguous`. This is described in
the founder notes of the batch 3 and 4 adjudication reports. The AI's decisions in
`comparison/adjudication_ai.xlsx` are unchanged. The strict reading changed 7 records from
exclude to ambiguous. No included record was affected, so the case list is the same under
either reading.

## Effect on results

None of the results that can be estimated depends on this deviation. Q4 is reported in full.
Q1, Q1b, Q2, Q3, Q5 and Q6 are reported as not estimable.

The results are provisional because the adjudication is AI-made (AMD-002). If a domain
adjudication made before any benchmark request produces E or I cases, it replaces the AI
adjudication. In that case the cohort is rebuilt with the same script. The request
generator, the baselines and the analysis script are then built, tested on synthetic and
development cases only, and locked under a new tag before any request. That would be
recorded as a further deviation.
