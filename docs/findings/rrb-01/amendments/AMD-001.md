# AMD-001: Two isolated AI extractions with founder adjudication and audit

Status: DRAFT, Date: 11/11/2026, takes effect when committed and tagged `rrb-01-amd-001`
Amends: locked protocol `rrb-01-protocol-v0.3.md` (tag `rrb-01-protocol-lock`, commit 4bb60f1c)
Reason: DEV-001 (the Stage 3 file was an AI extraction, not a founder extraction)

The locked protocol is not edited. This amendment replaces only the parts named below;
every other rule stays as locked (sources, extraction rules, schema, cohort rules,
baselines, metrics, analysis, evaluation lock).

## 1. Study description (replaces "Study type")

RRB-01 is an AI-extracted, externally sourced retrospective substitution retrieval
evaluation. Two isolated AI extraction runs apply the frozen extraction rules to two
published reviews. The founder adjudicates extraction disagreements and performs a
predefined audit of agreed records. Eligibility decisions have not been independently
verified by a materials-science expert. Agreement between AI runs is treated as
procedural reproducibility, not scientific validation.

## 2. Extraction (replaces the founder extraction and the rule-reproducibility check)

**Run A and Run B.** Two AI extraction runs, each in a fresh session that has never seen
this project, its history, DEV-001's file, or the other run's output: a new chat outside
the MaterialGraph Project with memory off, or the API, with no connectors or web access.
The assistant that produced the DEV-001 file is not used.

**Identical inputs.** Both runs receive only the Stage 4 package built from the locked
protocol (`ai_extraction_rules.md` SHA-256 56BCD216…, `ai_extraction_prompt.md` SHA-256
F78AA952…, page convention `pdf_index`) and the two frozen source PDFs (Hwang 6832B1BC…,
Noerochim 8D8991D4…).

**What the two runs are.** Isolated automated applications of the same protocol, not
independent scientific extractions. Three properties are distinguished:
- Session isolation (required): neither run sees the other run's output, previous
  project discussions, or the DEV-001 file.
- Model diversity (where available): different models, from different providers.
- Scientific independence: not achieved; there is no independent materials-science
  reviewer.

**Models.** Two different models, from different providers where possible. Provider
diversity is not treated as proof of independence. For each run, record: interface,
exact model name and version, configuration, prompt as sent, files and their SHA-256,
execution date and time, and the full transcript.

**Allowed follow-up messages.** Only these:
- "continue" (for long output);
- a format-only correction: the validator's error lines returned verbatim to the same
  session, at most twice;
- one fixed coverage question, sent after the output is complete: "List every page of
  each PDF that you did not fully process, or reply 'none'."

Every version is preserved. Whatever the run returns is its output; the founder never
edits a run's records.

**Coverage reporting.** A continuation message is never treated as evidence that every
page was processed. For each run, the report states the run's answer to the coverage
question and a mechanical page check: for each source, the pages that have at least one
record and the pages that have none. Pages with zero extracted records are reported
as a coverage diagnostic, not automatically classified as unprocessed; a page may
contain no qualifying statements. A run's self-reported coverage is distinguished from
independently verified coverage, which this study does not have. If a run reports pages it did not process, or
stops before the end of either PDF, its coverage is reported as incomplete for those
pages; the run is not extended or repeated to fill the gap without a further amendment.

**Upload limits.** If an interface cannot accept a frozen PDF unchanged, that interface
is not used. Any other handling requires a further amendment before the run.

**Preservation.** For each run: raw CSV, workbook, JSONL, converter report, run log and
transcript are committed before any comparison. The two runs are labelled `run_a` and
`run_b` in file names and run logs (the schema's `extractor` field is `ai` for both).

## 3. Comparison and adjudication

**Comparison.** Run A and Run B are compared with the locked comparison keys. Every
unmatched record is a disagreement, including a passage extracted by one run and
missed by the other.

**Adjudication.** The founder resolves every disagreement against the source PDFs using
only the locked rules, recording the decision, the rule applied and the reason. A
disagreement the rules cannot resolve is marked ambiguous (status P).

**Agreement audit (predefined).**
- All records that both runs include are checked by the founder against the PDF:
  the relationship is stated, the direction is stated, and both compositions are
  transcribed exactly.
- A fixed sample of records that both runs exclude is checked. Sampling is done by
  script after the two runs are matched and before any audit decision. The N jointly
  excluded records are ordered by Run A's (source, page, record number). Positions
  1, 6, 11, 16, … are selected; if fewer than min(10, N) records are selected, the
  earliest unselected records are added until the sample holds min(10, N) records.
- Each audited record is recorded as confirmed, or as an error with its type and the
  corrected decision. Corrections enter the adjudication record with a reason.
- The report states how many records were audited and how many errors were found,
  by type and by run. The audit can correct observed mistakes; it cannot establish
  that every omitted passage has been found.

**Final cohort derivation.** The final qualifying pair list is derived from the union
of both AI extractions after disagreement adjudication and the predefined agreement
audit. Every correction is recorded without modifying either original extraction.
Corrections to jointly included or jointly excluded records affect the final cohort
according to the locked eligibility rules; for example, a jointly excluded record found
to contain a qualifying directed pair enters the cohort through its recorded
correction. No case is silently added, removed or reclassified.

**Assistance.** For every adjudication and audit decision, record whether any help was
used (a person, or a tool or AI), and which. Undisclosed assistance is not permitted.

**Preservation.** Run A, Run B and the adjudication record are all preserved. The final
case list is derived from them by script and never replaces them.

## 4. Coverage limitation (added to threats to validity)

Agreement between the two runs is not evidence of complete enumeration: a passage both
runs miss is invisible to the comparison. The report states that full enumeration was
attempted by two automated runs, not independently established.
