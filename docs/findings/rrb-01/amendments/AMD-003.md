# AMD-003: Included records whose composition is a label

Status: DRAFT, takes effect when committed and tagged `rrb-01-amd-003`
Amends: cohort construction (Stage 6). Everything else stays as locked (protocol,
AMD-001, AMD-002).
Reason: the AI adjudication (AMD-002) included records whose recorded parent or target is
a label rather than a formula, for example "NMC111" (ADJ-032, ADJ-033, ADJ-061, ADJ-062).
The cohort is built from normalized formulas, and a label cannot be normalized. This rule
is fixed after adjudication and before cohort construction and before any confirmatory
benchmark request.

## Rule

An included record whose recorded composition does not normalize counts in the cohort
only if all of the following hold:

1. The recorded composition is a label (an abbreviation or name such as "NMC111"), not a
   formula with a variable, placeholder, coating or other excluded feature.
2. The same PDF page explicitly prints a single fixed formula for that label, as a
   definition (for example "LiNi1/3Mn1/3Co1/3O2 (NMC111)").
3. The resolution is recorded in `comparison/label_resolutions.csv`, one row per label and
   page, with: label, formula as printed, source, page, the exact text that defines it,
   the record IDs it applies to, and who verified it.
4. The founder has verified each row by opening the PDF at that page and finding the
   defining text with Ctrl+F (a text check; no chemistry judgment). The file is committed
   before the cohort is built.

The printed formula is normalized with the standard normalizer. If it does not normalize,
the record does not count.

An included record whose composition does not normalize and does not meet all four
conditions is reported with status P, reason `label_unresolved`, and does not count.
The AI adjudicator's decisions in `adjudication_ai.xlsx` are not changed.

## Reporting

The report lists every label resolution and every `label_unresolved` record.
