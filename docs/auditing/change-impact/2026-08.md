# MaterialGraph Change Impact History — 2026-08

Append-only record of externally visible and system-level behavior changes.

## Semantic validation of discovery element filters

Related finding: MG-AUD-093  
Date: 2026-08-06  
Release reference: Post-v1.9.18  
Status: Resolved; full-suite test-verified and lint-verified

### Before

Discovery element filters enforced only string length. A nonexistent symbol
such as `Xx` could pass the public API boundary, while validating against the
partial element table would have incorrectly rejected recognized elements not
yet represented in MaterialGraph data.

### After

A centralized catalogue of all 118 recognized chemical element symbols now
validates and normalizes `avoid_element` and `prefer_element` consistently
across all seven discovery GET routes. Unknown symbols return `422`; valid
symbols absent from the current dataset, such as `Cu`, remain accepted.

### Impact

- Scientific result: **Invalid element-filter requests are rejected before discovery processing**
- Ranking: **No algorithm change**
- API contract: **Yes; recognized symbols are normalized and unknown symbols return `422`**
- Dataset coverage: **Unchanged and kept separate from chemical-symbol validity**
- Data migration: **No**

## Atomic PostgreSQL graph-job claiming

Related finding: MG-AUD-060  
Date: 2026-08-07  
Release reference: Post-v1.9.18  
Status: Resolved; PostgreSQL concurrency-tested and full-suite verified

### Before

Pending graph jobs were selected without a row lock. Concurrent workers could
read the same oldest `PENDING` row before either committed its transition,
allowing the same job to be claimed and executed more than once.

### After

Pending-job selection uses `FOR UPDATE SKIP LOCKED`, a one-row limit, and
deterministic ordering by creation time and job ID. The selected row is changed
to `RUNNING` and committed before it is returned to the worker. A worker skips
rows already locked by another claim transaction.

### Impact

- Job execution: **Concurrent workers no longer claim the same pending row**
- Ordering: **Deterministic oldest-first selection with job-ID tie-breaking**
- API contract: **No public schema change**
- Scientific result: **No scoring, ranking, graph, pathway, or evidence change**
- Database schema: **No change required**
- Remaining scope: **Contradictory lifecycle transitions remain open under MG-AUD-061**
- Operational verification: **Full suite passed on isolated `materialgraph_test`; the temporary Windows override is removed with `set DATABASE_URL=` before returning to normal `.env` configuration**

## Atomic graph-job terminal transitions

Related finding: MG-AUD-061  
Date: 2026-08-09  
Release reference: Post-v1.9.18  
Status: Resolved; PostgreSQL concurrency-tested, full-suite verified, and lint-verified

### Before

Graph jobs could be completed or failed regardless of their current persisted
state. Pending or already terminal jobs could therefore be moved into an
out-of-order or contradictory terminal state, and competing completion and
failure attempts were not guarded atomically.

### After

Completion and failure use atomic conditional updates that succeed only when
the current state is `RUNNING`. Valid transitions are limited to
`RUNNING -> COMPLETED` and `RUNNING -> FAILED`; invalid, repeated,
contradictory, and missing-job attempts return `None`. One timestamp is used
for both terminal completion and update metadata.

### Impact

- Job lifecycle: **Only a running job can enter a terminal state**
- Concurrency: **Competing terminal attempts allow exactly one success**
- Internal contract: **Invalid state or missing job returns `None` without mutation**
- API contract: **No public schema change**
- Scientific result: **No scoring, ranking, graph, pathway, or evidence change**
- Database schema: **No change required**
- Verification: **545 tests passed; Ruff passed for the changed service and test files**
- Operational safety: **Tests ran on isolated `materialgraph_test`; normal `materialgraph` configuration was restored and verified**
- Remaining scope: **The orphaned `job_status` enum on migration downgrade remains a separate follow-up**

## Closed limited-neighborhood graph references

Related finding: MG-AUD-063  
Date: 2026-08-11  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Neighborhood nodes and edges were truncated independently. A limited response
could therefore include an edge whose source or target node was absent from
the returned node collection.

### After

The service selects the limited node set first, derives its material IDs, and
then retains only edges whose two endpoints are both present before applying
the edge limit. A one-node neighborhood contains the root and no edges.

### Impact

- Graph integrity: **Every returned edge references two returned nodes**
- Boundary behavior: **`limit=1` returns the root and zero edges**
- Response counts: **Node and edge counts match their returned collections**
- API contract: **No public schema change**
- Scientific result: **No score, ranking, pathway, or evidence semantic change**
- Database schema: **No change required**
- Verification: **4 focused tests and 549 full-suite tests passed; Ruff passed for both changed files**

## Batched similarity criticality loading

Related finding: MG-AUD-071  
Date: 2026-08-13  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Similarity loaded criticality separately for the source and each distinct
candidate. Query count therefore grew with the limited candidate set despite a
request-local cache preventing duplicate material lookups.

### After

The service determines the limited candidate set first and makes one bulk
criticality request containing the source material and those candidate IDs.
Candidate scoring and explanation then reuse the returned material-ID map.

### Impact

- Performance: **Criticality loading is one bulk operation per similarity request**
- Limit behavior: **Only the source and candidates selected by `limit` are loaded**
- Unknown evidence: **Unknown criticality remains `None` and its direction remains `UNKNOWN`**
- Ranking: **Existing similarity and deterministic tie-order semantics are unchanged**
- API contract: **No public schema or response-semantic change**
- Database schema: **No change required**
- Verification: **16 focused tests and 551 full-suite tests passed; Ruff passed for both changed files**

## Explicit risk and criticality evidence semantics

Related findings: MG-AUD-021, MG-AUD-022, MG-AUD-023, MG-AUD-024, MG-AUD-025  
Date: 2026-08-18  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Risk and criticality reused overlapping element-profile dimensions without
declaring that shared evidence basis. Score-calculable partial profiles could
appear complete because only element-level calculability was measured, and
legacy numeric risk APIs represented unknown evidence as `0.0`.

### After

A shared evidence policy declares provenance, shared and metric-specific
dimensions, and each aggregation method. Responses distinguish score-eligible
element coverage from complete-profile and dimension coverage. Completeness
requires every expected dimension for every element. Unknown risk is returned
as `None`/JSON `null` by public, scalar, and bulk APIs.

### Impact

- Evidence interpretation: **Partial calculability is no longer presented as complete evidence**
- Provenance: **Risk and criticality explicitly disclose their shared upstream evidence**
- Aggregation: **Existing equal-element risk and composition-weighted criticality policies are preserved and named**
- API contract: **Unknown material risk changes from `0.0` to `null`; evidence metadata is expanded**
- Scientific calculation: **No existing calculable score formula changed**
- Database schema: **No migration required**
- Verification: **25 focused tests and 581 full-suite tests passed; Ruff passed for all affected files**

## Evidence-origin transparency and endpoint risk coverage

Related findings: MG-AUD-028, MG-AUD-029  
Date: 2026-08-18  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Generic signal confidence and readiness terminology could make deterministic
internal support appear equivalent to literature, experimental, DFT, or other
external scientific evidence. Endpoint ranking also received risk scores
without the complete-profile and dimension coverage needed to interpret them.

### After

Evidence summaries identify internal deterministic origin, unvalidated status,
confidence scope, external-evidence availability, readiness scope, and the
researcher decision boundary. Material quality propagates risk coverage and
provenance to endpoint evidence. Partial risk remains visible but receives an
`unknown` risk band and cannot create favorable within-tie differentiation.

### Impact

- Evidence interpretation: **Internal rule support is explicitly distinct from external scientific validation**
- Risk interpretation: **Endpoint risk values travel with completeness and coverage metadata**
- Tie handling: **Partial low-risk evidence cannot create a favorable endpoint risk band**
- Ranking scores: **Scientific usefulness scores and quality formulas are unchanged**
- Readiness: **Existing thresholds are unchanged and explicitly scoped to internal prioritization**
- API contract: **Additional evidence-origin, validation, scope, coverage, and provenance fields**
- Database schema: **No migration required**
- Verification: **47 focused tests and 584 full-suite tests passed; Ruff passed for all changed files**

Date: 2026-08-18  
Release reference: 0.1.0 / Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Standard requirements installation selected an editable pinned checkout of
MaterialGraph from a different repository location. Getting-started guidance
configured an API-key name the importer did not consume. Package, Settings,
and FastAPI metadata independently reported conflicting versions.

### After

### Impact

- Build provenance: **Dependency installation cannot silently select another MaterialGraph checkout**

## Normalized composition membership persistence

Related finding: MG-AUD-059  
Date: 2026-08-19  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

The import pipeline normalized and deduplicated candidate element membership
when resolving composition fractions, but persistence subsequently iterated the
original raw element list. Duplicate or whitespace-variant membership could
therefore attempt multiple `MaterialElement` rows for the same normalized
material-element identity and conflict with the database uniqueness constraint.

### After

Material-element persistence iterates the normalized fraction mapping directly.
Each normalized symbol is persisted once with its resolved fraction. Existing
validation and the legacy unknown-weight fallback remain unchanged.

### Impact

- Composition identity: **Normalized element membership is honored during persistence**
- Import reliability: **Duplicate raw membership no longer produces duplicate material-element links**
- Fraction semantics: **Resolved normalized fractions are persisted without recomputation**
- Legacy behavior: **Missing composition fractions still use the existing `1.0` unknown-weight fallback**
- API contract: **No change**
- Database schema: **No migration required; the existing uniqueness constraint remains authoritative**
- Verification: **25 focused tests and 592 full-suite tests passed; Ruff passed for all affected files**

## Explicit discovery constraint policies and strict hard rejection

Related findings: MG-AUD-016, MG-AUD-017  
Date: 2026-08-19  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Discovery candidate scoring applied bonuses and penalties for preferred and
avoided elements without explicitly declaring that the constraints were soft.
Objective exploration exposed a `strict` mode, but violating candidates could
remain ranked; its warning stated that strict mode should reject them without
performing the rejection.

### After

Discovery candidate responses expose typed, machine-readable soft constraint
semantics. Strict objective exploration filters chains before ranking and
limiting: every non-root material must avoid every requested avoided element.
Preferred elements remain soft bonuses. Balanced and exploratory modes retain
their existing soft behavior.

### Impact

- Candidate discovery: **Avoided elements are explicitly soft penalties and preferred elements are soft bonuses**
- Strict exploration: **Violating non-root chain materials and their candidates are hard-rejected**
- Starting material: **The root may contain an avoided element that the objective seeks to remove**
- Balanced/exploratory modes: **Existing soft scoring behavior is preserved**
- API contract: **Additive typed `constraint_policy` metadata**
- Scientific scoring: **Existing bonus and penalty values are unchanged**
- Database schema: **No migration required**
- Verification: **47 focused tests and 596 full-suite tests passed; Ruff passed for all affected files**

## Composition-heuristic family and substitution semantics

Related findings: MG-AUD-018, MG-AUD-019, MG-AUD-020  
Date: 2026-08-19  
Release reference: Post-v1.9.18  
Status: Resolved; focused, full-suite, and lint verified

### Before

Family and substitution rules were deterministic composition heuristics, but
their responses and explanations could be read as validated structural-family
or substitution-mechanism claims. Multiple implementations also included Mg
in an alkali-like element set even though Mg is an alkaline-earth metal.

### After

Family, substitution-path, transition, and graph-edge results explicitly
identify their internal composition-heuristic basis and state that structural
families and substitution mechanisms are not validated. A shared canonical
alkali-metal taxonomy includes Li, Na, K, Rb, Cs, and Fr and excludes Mg.

### Impact

- Scientific claims: **Explanations are calibrated to composition-level hypotheses**
- Family API: **Additive relationship-basis and structural-validation metadata**
- Discovery API: **Additive plausibility-basis and mechanism-validation metadata**
- Taxonomy: **Mg no longer receives alkali-substitution classification**
- Scoring: **Existing relationship identifiers and numeric heuristic scores are preserved**
- Database schema: **No migration required**
- Verification: **44 focused tests and 600 full-suite tests passed; Ruff passed for all affected files**
