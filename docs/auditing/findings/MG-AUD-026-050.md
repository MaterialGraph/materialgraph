# MaterialGraph Audit Findings MG-AUD-026–050

Detailed finding records migrated from the pre-reorganization architecture audit. Current status is authoritative only in `../AUDIT_REGISTER.md`.

### MG-AUD-026 — Material Quality Scale Is Intentionally 0--15

- **Status:** Resolved
- **Priority:** P1
- **Confidence:** Confirmed

**Finding:** `QUALITY_SCORE_MAX = 15.0`.

Allocation:

-   stable flag: 5.25
-   very low energy above hull: 5.25
-   low criticality: 2.25
-   low known risk: 2.25

No missing multiplication bug was found.

### MG-AUD-027 — Stability and Energy Are Imported Separately but Reused

- **Status:** Confirmed behavior; policy open
- **Priority:** P2
- **Confidence:** Confirmed implementation / Medium policy

**Finding:** `is_stable` and `energy_above_hull` are imported separately from
Materials Project.

Both are rewarded in:

-   quality
-   similarity
-   recommendation

Repeated weighting is confirmed. Scientific appropriateness remains a
policy question.

### MG-AUD-028 — Internal Deterministic Support Can Look Like Scientific Evidence

- **Status:** Resolved
- **Priority:** P1
- **Confidence:** Confirmed

**Finding:** Framework-derived and other internal signals can increase
evidence/readiness even when external evidence is absent.

Future semantics should distinguish:

-   internal support strength
-   external evidence readiness
-   evidence coverage
-   validation readiness

**Resolution:** Evidence summaries now label their support basis as internal
and deterministic, state that external evidence is not integrated, scope
readiness to internal research prioritization, and include a researcher
decision boundary. Every supporting signal exposes its internal origin,
unvalidated scientific status, and confidence scope. Missing literature,
experimental, DFT, electrochemical, and manufacturing evidence is explicitly
classified as external and not integrated. Readiness thresholds and scientific
scores are unchanged.

### MG-AUD-029 — Risk Coverage Is Not Fully Propagated to Endpoint Evidence

- **Status:** Resolved
- **Priority:** P1
- **Confidence:** Confirmed

**Finding:** Equal numeric risk values can represent different evidence coverage
states.

Values and coverage should travel together when downstream decisions
depend on them.

**Resolution:** Material quality now propagates score-eligible, complete-profile,
and dimension-level risk coverage together with provenance, completeness,
partial-profile elements, and unknown elements. Endpoint evidence retains the
raw nullable risk score for transparency but assigns a risk ordering band only
when risk is known and evidence-complete. Partial low-risk evidence therefore
cannot create a favorable within-tie ordering signal. Existing quality and
scientific usefulness score formulas are unchanged.

## Discovery, Ranking, and Search Space

### MG-AUD-030 — Bounded Search Shapes the Opportunity Set

- **Status:** Resolved
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** -   objective filtering occurs after bounded chain generation
-   completed-chain limit shapes discovery, not only presentation
-   candidate expansion is bounded per node
-   search order can affect which opportunities survive

``` text
production search bounds ≠ scientific completeness
```

Do not remove production guards blindly.

**Resolution:** The requested response limit no longer terminates chain
traversal. Discovery now builds a bounded breadth-first search pool using an
independent 200-state budget while retaining the six-candidate per-material
expansion bound. Objective filters and scientific ranking operate on that
bounded pool before the requested result limit is applied. Responses expose
typed search-budget, truncation, generated-count, and returned-count metadata
and explicitly state that scientific completeness is not guaranteed.

### MG-AUD-031 — Family Ordering Can Affect Bounded Discovery

- **Status:** Resolved
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Family candidates are ordered by:

1.  relationship-label count
2.  shared-element count

Correlated labels derived from the same composition facts can multiply
search priority.

**Resolution:** Relationship-label count no longer determines family
candidate priority. Candidates are ordered by shared-element count descending,
then by material ID ascending. This preserves a composition-level continuity
heuristic without multiplying priority for correlated labels.

### MG-AUD-032 — Equal-Key Family Ordering Lacks a Final Tie-Breaker

- **Status:** Resolved
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Equal-key candidates can inherit database-return order.

Under bounded expansion, this can affect which chains survive.

**Resolution:** Material ID is now the deterministic final family-ordering
tie-breaker. Equal-evidence candidates therefore produce the same traversal
order regardless of database return order.

**Verification:** 41 focused service and API tests and the 605-test full suite
passed. Ruff passed for every affected service, schema, and test file.

### MG-AUD-033 — Recommendation Pipeline Contains Irreversible Preselection

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** ``` text
structured neighbors
→ neighbor ranking
→ top-N truncation
→ similarity scoring
→ recommendation scoring
→ scenario evaluation
```

Candidates excluded before similarity scoring cannot be recovered later.

The upstream and similarity stages share the same 2:3
element/application weighting ratio, which makes the gate coherent but
still irreversible.

**Resolution:** Similarity now evaluates the complete structured-neighbor
pool, bulk-loads criticality for that pool, applies its ranking policy, and
only then applies the requested result limit. Recommendation and scenario
ranking likewise operate on the complete similarity or recommendation pool
before their final slices. Responses disclose candidate-pool and returned
counts.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-034 — Recommendation Defaults to Lower Criticality

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed implementation

**Finding:** `get_recommendations()` defaults `prefer_lower_criticality=True`.

Scenario recommendations also force this preference in their base
recommendation stage.

Whether this is appropriate for every objective remains open.

**Resolution:** General recommendation, scenario, and discovery-candidate
paths are now neutral by default. The public recommendation and scenario APIs
retain an explicit `prefer_lower_criticality` opt-in, and typed response
metadata reports whether the preference was applied and its effective delta
multiplier. Research-objective workflows retain their independently explicit
objective policy.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-035 — Similarity and Recommendation Use Different Criticality Policies

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** -   similarity tie ordering prefers smaller absolute criticality
    difference
-   recommendation scoring prefers lower criticality

These are layered policies, not necessarily contradictions.

**Resolution:** The layers now expose typed, distinct policies. Similarity is
neutral and uses known criticality followed by the smallest absolute delta
only as a tie-breaker after equal similarity. Recommendation applies lower-
criticality weighting only when explicitly requested. Discovery no longer
adds a second fixed lower-criticality bonus after recommendation scoring.
Material ID is the deterministic final recommendation and scenario
tie-breaker.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-037 — Recommendation Reasons Mix Contributors and Context

- **Status:** Resolved
- **Priority:** P1
- **Confidence:** Confirmed

**Finding:** Reasons can:

-   mention criticality when the preference flag is disabled
-   omit the low-energy score contribution
-   include shared elements/applications as context even when not
    directly added in recommendation scoring

Contributor facts and contextual facts are not distinguished.

**Remediation:** Recommendation explanation generation now receives
`prefer_lower_criticality` and distinguishes the similarity basis, active score
contributors, contextual criticality information, and the final recommendation
score. Shared elements and applications are labelled as components of the
similarity score rather than independent recommendation bonuses. The
low-energy-above-hull contribution is included when its scoring condition
(`energy_above_hull <= 0.01`) is satisfied. Criticality is presented as an
active contributor only when the preference is enabled; otherwise it remains
available under `context`.

**Verification:** Focused recommendation-service tests and the full regression
suite passed locally. Local and production endpoint checks for material 5
confirmed that
`prefer_lower_criticality=true` includes criticality in scoring and that
`prefer_lower_criticality=false` excludes it from the score while retaining the
comparison as context. Displayed recommendation scores reconciled with their
stated contributors in both modes. Production verification passed on
2026-07-23.

### MG-AUD-038 — Path Efficiency Is Hop-Count Based

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Equal-hop paths receive equal path-efficiency contributions,
contributing to score collapse.

**Resolution:** Hop count remains the base path cost, but efficiency now also
measures productive transition progress. A later transition that reverses an
earlier element introduction or removal reduces the efficiency contribution,
so equal-hop paths no longer necessarily receive equal credit. Transition
plausibility remains a separate score component.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-039 — Path Material Quality Is Averaged Across the Path

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** ``` text
A → B → C
path quality = average(quality(A), quality(B), quality(C))
```

Shared bases/intermediates can dilute endpoint differences.

**Resolution:** Whole-path arithmetic averaging was replaced by the geometric
composition of endpoint quality and the weakest material-quality score on the
path. Endpoint differences therefore remain visible, while a weak
intermediate continues to act as a path bottleneck. The existing 15-point
allocation and public `material_quality` score-breakdown key are preserved.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-040 — Exploration Attribution Can Use Future Transitions

- **Status:** Resolved
- **Priority:** P1
- **Confidence:** Confirmed

**Finding:** For `A → B → C`, candidate B can receive reasons or bonuses using
`B → C`, even though that transition did not produce B.

**Resolution:** Candidate scoring and explanation now receive only the causal
transition prefix ending at that candidate. For `A → B → C`, candidate B uses
only `A → B`, while candidate C uses both `A → B` and `B → C`. Intermediate
candidates can no longer receive bonuses or reasons from future transitions.
Existing scoring constants and completed-path behavior are unchanged.

**Verification:** 12 focused tests and the 606-test full suite passed. Ruff
passed for the affected service and regression tests.

## Comparison, Endpoint Ranking, and Contracts

### MG-AUD-041 — Endpoint Ranking Uses Implicit Lexicographic Policy

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Ordering:

``` text
quality
→ stability
→ energy above hull
→ criticality
→ risk
→ evidence readiness
```

Earlier dimensions dominate later ones.

Do not replace with weighted scoring without policy justification.

**Resolution:** Endpoint-sensitive ranking now explicitly reports a
`lexicographic` ordering policy and publishes the precedence of every grouping
dimension. No weighted score was introduced, and raw endpoint evidence remains
available for researcher inspection.

**Verification:** Eight endpoint-sensitive ranking tests passed. The full
577-test suite passed, and Ruff passed for the affected research services and
tests.

Status: **Remediated and test-verified on 2026-08-16.**

### MG-AUD-042 — Exact Numeric Differences Can Split Evidence Groups

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Tiny numeric differences can separate endpoints without a defined
precision or meaningful-difference policy.

Do not add arbitrary epsilon thresholds.

**Resolution:** Evidence equality uses existing MaterialGraph producer
precision and quality-policy thresholds rather than an arbitrary epsilon.
Quality and stability use their two-decimal producer precision; energy above
hull, criticality, and risk use the established quality-policy bands; evidence
readiness retains its categorical order. Raw measurements are not mutated.

**Verification:** Endpoint regressions prove that values within an existing
policy band preserve a tie while values crossing a policy boundary are
differentiated. Eight focused tests and the full 577-test suite passed. Ruff
passed.

Status: **Remediated and test-verified on 2026-08-16.**

### MG-AUD-043 — Comparative Summaries Are Not Uniformly Tie-Aware

- **Status:** Remediated
- **Priority:** P1
- **Confidence:** Confirmed

**Finding:** Some layers preserve ties, while:

-   `top_ranked_pathway`
-   highest-readiness summaries
-   legacy candidate comparison

can select one representative.

**Resolution:** Highest-readiness comparative summaries now report `unique` or
`tie`, return every pathway sharing the highest readiness, and populate legacy
singular pathway fields only for a unique result. Existing top-score summaries
retain canonical two-decimal tie handling. Legacy candidate comparison already
returns explicit, request-order-independent ties using its complete decision
key and required no production change.

**Verification:** Twenty-nine comparative-research tests and eight legacy
candidate-comparison tests passed. The full 577-test suite passed. Ruff passed
for both changed services and their tests.

Status: **Remediated and test-verified on 2026-08-16.**

### MG-AUD-044 — Comparison Conflates Filtered and Unavailable Candidates

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** If either candidate does not survive screening, comparison returns no
result without distinguishing:

-   missing material
-   filtered by stability
-   filtered by energy threshold
-   otherwise unavailable

**Resolution:** Candidate comparison now requests targeted screening
evaluations for the two material IDs. Each candidate receives an explicit
disposition: `eligible`, `material_not_found`, `filtered_unstable`,
`filtered_energy_above_hull`, or `unavailable`. Successful comparison payloads
remain unchanged. The API returns structured `404` details for nonexistent
materials and structured `422` details for materials excluded by the selected
screening constraints.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-045 — API Contracts Are Under-Typed or Semantically Broader Than Implementation

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** High

**Finding:** Issues include:

-   multi-element objective promise exceeds scalar handling
-   requested `preserve_elements` differs from inferred
    `preserved_framework`
-   evidence readiness is an unconstrained string
-   confidence scope is ambiguous
-   nested quality/comparison structures are under-typed
-   objective validation remains open for casing, invalid symbols,
    empties, and contradictions

Type contracts should strengthen after semantic stabilization.

**Resolution:** The stabilized scientific-pathway response contract now uses
concrete Pydantic models for pathway materials and transitions, scientific
score components, material-quality evidence, comparative summaries, pairwise
comparisons, evidence readiness, and endpoint-sensitive ranking groups.
Evidence-readiness, confidence, objective-satisfaction, quality, comparison,
and endpoint-ranking states are constrained to their implemented values.
Pathway confidence now carries an explicit scope stating that it represents
deterministic pathway ranking rather than external scientific validation.
The public analysis response no longer accepts generic dictionaries as
alternatives to the typed pathway-comparison and endpoint-ranking models.
Intentionally extensible structures, including discovery-candidate score
breakdowns and endpoint grouping-policy metadata, remain mappings.

Status: **Remediated and test-verified on 2026-08-21.**

## 4.6 Production and Performance

## Production and Performance

### MG-AUD-046 — Family Discovery Performs Global Scans

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Each family request loads the global material-element map and scans
non-test materials in Python.

**Resolution:** Family discovery now first identifies candidate material IDs
through indexed material-element overlap with the base composition. It loads
composition rows only for that bounded candidate scope and returns the scoped
map for request-local reuse. Relationship classification and deterministic
ordering remain unchanged.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-047 — Candidate Screening Has N+1 Access Patterns

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Screening loads all materials, then performs per-material:

-   element lookup
-   risk lookup

Bulk risk capabilities already exist.

**Resolution:** Screening now gathers all material IDs once, bulk-loads their
element symbols in one query, and uses the existing bulk risk-signal API once.
The per-material loop performs only in-memory lookup, filtering, scoring, and
response construction.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-048 — Candidate Service Duplicates Global Element-Map Loading

- **Status:** Remediated
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** `MaterialFamilyService` and `DiscoveryCandidateService` can each load
global material-element mappings in the same request path.

**Resolution:** Candidate discovery now consumes the scoped composition map
returned by family discovery. Recommendation and scenario stages extend that
same request-local map only for candidate IDs not already loaded, eliminating
the second global map query while preserving exact stored composition and the
explicit-empty-membership boundary.

Status: **Remediated and test-verified on 2026-08-20.**

### MG-AUD-049 — Community Analytics Uses Raw Formula Substring Matching for Element Membership

- **Status:** Resolved
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** `DiscoveryGraphAnalyticsService._summarize_community()` determined configured
element membership by checking raw element-symbol substrings against chemical
formula text.

Conceptually:

``` text
element in formula
```

Chemical formulas are structured scientific data. Raw substring membership is
not a valid general exact-element-membership test.

The configured symbol set limited obvious collisions in the current dataset,
but the implementation was structurally unsafe and could misclassify membership
as the supported element vocabulary expanded.

**Impact:** The affected dependency chain was:

``` text
formula substring membership
→ element_counts
→ dominant_elements
→ researcher-facing community summary
```

Dependency inspection confirmed that these counts did not feed:

- community membership
- connected-component detection
- greedy modularity community detection
- degree centrality
- betweenness centrality
- closeness centrality
- hub selection
- density
- average degree
- average quality score
- average edge score
- community importance score

No numeric graph-ranking or community-scoring defect was confirmed.

### MG-AUD-050 — Scientific Pathway Responses Did Not Distinguish Path-Wide and Endpoint-Specific Objective Satisfaction

- **Status:** Resolved
- **Priority:** P2
- **Confidence:** Confirmed

**Finding:** Scientific pathway responses exposed:

- requested objective elements
- matched objective elements
- unmatched objective elements
- objective coverage
- completion status

These correctly described deterministic path-wide transition evidence.

However, they did not distinguish whether the final endpoint material
itself satisfied the requested research objective.

**Impact:** No scientific scoring defect existed.

Objective alignment, deterministic traversal, scientific usefulness,
transition plausibility, and pathway ranking were already correct.

The limitation affected researcher explainability only.

Researchers could not immediately distinguish:

- objective satisfied somewhere along the pathway
- objective satisfied by the final endpoint material
