# Objective Explore mode policy (Release 1, contract P)

**Scope: Objective Explore only** (`POST /api/v1/materials/{id}/discovery/objective/explore`;
register entry 37, condition d). Discovery candidates, the Objective Chains
API (`/discovery/objective/chains`) and Scientific Pathway Analysis keep their
own behaviour and are not governed by this policy.

## One executable source

`app/domain/objective_mode_policy.py` defines one `ModePolicy` per mode
(`balanced`, `exploratory`, `strict`). Everything below reads from it:

| Behaviour | Where it is applied |
|---|---|
| Admission flags (Strict hard-avoid; one reserved slot per preferred element) | `ResearchObjectiveExplorationService.explore` |
| Rejection of steps that introduce an avoided element | transition validation (forwarded only if a policy differs from the validator's default; none does today) |
| Strict returned-chain filter (non-source materials, formula symbols) | `_apply_mode_constraints` |
| Candidate prefer bonus, avoid penalty and score offset | `_score_material` |
| `constraint_policy`, `avoid_policy`, `prefer_policy`, `candidate_score_offset` in the response | generated by the policy object |
| Mode explanations, coverage `avoid_policy_explanation`, warnings | generated by the policy object |
| Mode descriptions shown before a request | `GET /api/v1/discovery/objective-modes` (the client keeps no copy and shows an explicit "unavailable" state on failure) |

## Encoded behaviour (unchanged from the baseline)

| | Balanced | Exploratory | Strict |
|---|---|---|---|
| Step introducing an avoided element | rejected | rejected | rejected |
| Avoided element already present (non-source) | allowed, −25 | allowed, −10 | excluded |
| Admission evidence | — | — | element records; materials without records excluded |
| Returned-chain filter | none | none | removes chains with an avoided element in any non-source material, read from formula symbols |
| Preferred elements | one reserved slot each, alphabetical under oversubscription; +15 | same | same |
| Score offset | 0 | +5 (does not change order) | 0 |
| `constraint_policy.avoid_elements` | `reject_introduced_penalize_inherited` | same | `exclude_non_source` |

Balanced and Exploratory generate the same chains (P-6). Strict's split
between element records at admission and formula symbols in the final filter
is disclosed here and pinned by tests; unifying it is Release 2 (P-7).

Responses recorded before Release 1 may carry the legacy values
`soft_penalty`, `hard_rejection` and `soft_bonus`; the frontend type keeps
them only so those records still render.
